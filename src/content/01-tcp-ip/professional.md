### 切り分けは下の層から、事実を積み上げる

**「Webが見られない」は症状です。原因は層ごとに確かめて絞り込みます。**

下の層が成り立たなければ、上の層も必ず失敗します。そこで、下から順に「どこまでは成立しているか」を確かめます。

| 層 | 確認の例 |
| --- | --- |
| リンク・ARP | リンクのUp/Down、`ip neigh` |
| IP | `ping`、`traceroute` |
| TCP | `nc -zv <宛先> 443` |
| TLS | `curl -v` の証明書エラー |
| HTTP | ステータスコード（200、503など） |

実行したコマンドと結果は、時刻つきで記録します。そのまま引き継ぎや報告に使えます。設定の変更は1つずつ行い、変えるたびに同じ確認を繰り返すと、何が効いたのかを説明できます。

### Connection refused と timeout は別の手がかり

**エラーの種類を見分けるだけで、調べる範囲が大きく絞れます。**

- **Connection refused（接続拒否）**：拒否の応答（主にRST）が返ってきた状態です。相手のホストまでは届いていて、そのポートで待ち受けていない（またはRSTで拒否された）ことを示します。
- **timeout（時間切れ）**：何も返らないまま時間が過ぎた状態です。途中のFirewallでの破棄、経路の欠落、ホストの停止などを疑います。

ただし、FirewallがRSTやICMPのDestination Unreachableを返して拒否することもあります。エラーだけで決めつけず、経路上の機器のログも確認します。

### ICMPをすべて遮断しない

「セキュリティのためICMPは全部止めよう」という案が出ることがあります。止めると、pingが使えなくなるだけでは済みません。

Path MTU Discovery（経路上で通れる最大サイズを探る仕組み）に必要な、Fragmentation NeededやPacket Too Bigも届かなくなります。すると「小さな通信は通るのに、大きな応答だけ止まる」というわかりにくい障害が起きます。

IPv6では、相手のMACアドレスを調べるNDP（近隣探索）もICMPv6で動きます。IPv4以上に、一律の遮断はできません。許可するICMPの種類を決めて、ポリシーとして文書化しておきます。

### MTUはトンネルやVPNで小さくなる

**「接続はできるのに、大きなデータの転送だけ固まる」ときはMTUを疑います。**

VPNやトンネルは、元のパケットに新しいヘッダを追加して運びます。そのぶん、中を通せるパケットは1500バイトより小さくなります。

Linuxでは、DF（分割禁止）を立ててサイズを指定したpingで、経路のMTUを確かめられます。

```text
ping -M do -s 1472 <宛先>
  1472（データ）＋ 8（ICMPヘッダ）＋ 20（IPヘッダ）＝ 1500バイト
  通らなければ -s を小さくして、通る大きさを探す
```

ルータ側では、TCP MSS（1つのTCPセグメントで運ぶデータの最大サイズ）を小さく調整して回避することもあります。

> このシミュレータはMTUを再現しないため、この確認は実機で行います。

### タイムアウトとアイドル切断を設計に含める

TCPの再送が続く間、アプリケーションは待たされます。Linuxの既定では、SYNに応答がない接続が失敗と判定されるまで2分程度かかることがあります。アプリ側の接続タイムアウトは明示的に決めておきます。

また、NAT・Firewall・ロードバランサは、一定時間通信のない接続の状態を消します。長時間の接続では、keepalive（通信がなくても定期的に小さなパケットを送る仕組み）の間隔を、その時間より短く設計します。

### 証明書の期限は監視で守る

TLSの障害で多いのは、暗号の問題よりも、証明書の期限切れや、SNI（接続先のサーバー名）と証明書の名前の不一致です。

有効期限を監視して事前に通知し、可能なら自動更新にします。更新では、中間証明書（サーバー証明書と発行元をつなぐ証明書）を含むチェーンの設定を忘れがちです。更新後は、外部から実際に接続して確認します。

### パケットキャプチャは両端で、時刻を揃えて

両端のキャプチャを比べると、原因の位置がわかります。

- 送信側で出ているのに、受信側に届いていない → 途中に原因がある
- 受信側に届いているのに、応答が出ていない → 受信側に原因がある

突き合わせのため、機器の時刻はNTP（時刻を合わせる仕組み）で揃えておきます。キャプチャには通信内容や認証情報が含まれることがあるので、取得範囲と保管方法にも注意します（第8章）。

### まとめ

- 「つながらない」は症状。下の層から、どこまで成立しているかを確かめて記録する。
- refusedは「相手（か途中の機器）まで届いている」、timeoutは「何も返ってこない」手がかり。
- ICMPは一律に止めず、必要な種類を決めて許可する。
- 大きなデータだけ止まるならMTU、放置すると切れるならアイドル切断を疑う。
- 証明書の期限は監視する。キャプチャは両端で、時刻を揃えて取る。
