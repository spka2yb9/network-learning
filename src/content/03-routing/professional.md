### 経路の設計理由を残す

**「なぜこの経路なのか」は、設定を見てもわかりません。**

なぜこの区間はStatic Routeで、なぜここはOSPFなのか。なぜこのコストなのか。構成図と一緒に、宛先ごとの想定経路と予備経路、その理由を文書にしておきます。

インターフェースの `description`（説明文を付ける設定）に接続先を書くだけでも、障害時の確認が速くなります。文書が実機と一致しているかは、定期的に `show ip route` と見比べて確かめます。

### Static Routeは、遠くの障害に気づかない

Static Routeは、出力インターフェースがUpで、Next Hopへの経路がある限り残り続けます。Next Hopのルータが止まっても、それだけでは消えません。

```text
R1 ── スイッチ ── R2（停止）
R1のリンクはスイッチとつながっているのでUpのまま
→ R2をNext HopとするStatic Routeが残り、パケットが捨てられ続ける
```

ブラックホールとは、パケットが届かずに捨てられ続ける状態です。冗長化が必要な区間では、動的ルーティングや、BFD（Bidirectional Forwarding Detection：隣のルータとの通信断を短い間隔で検知する仕組み）を組み合わせます。

### Default Routeは影響範囲が広い

Default Routeは知らない宛先をすべて吸い込みます。設定を誤ると、広い範囲のブラックホールやループになります。

拠点の経路を集約して広告するときは、次のようなループに注意します。

```text
拠点ルータ：10.1.0.0/16 を本社へ広告。自分のDefault Routeは本社向け
本社：存在しない 10.1.99.0/24 宛てを、10.1.0.0/16 に従って拠点へ送る
拠点：10.1.99.0/24 の経路がない → Default Routeで本社へ送り返す → ループ
```

対策の定石は、集約範囲をNull0（パケットを捨てる仮想の出口）へ向ける経路を置くことです。存在しないサブネット宛ては、拠点で捨てられます。

```text
ip route 10.1.0.0 255.255.0.0 Null0     （拠点ルータ。実機のCisco IOSの書き方）
```

Default Routeをどこから、どのルータへ配るかも設計で決めます。

### 往路と復路が違う経路になっていないか

冗長構成では、行きと帰りで別の経路を通る非対称ルーティングが起こりえます。

経路としては問題なくても、状態を持つFirewall（第6章）は片方向しか見えないため、通信を破棄することがあります。tracerouteは両側から実行し、往路と復路の両方を確認します。

### OSPFのNeighborは信頼の境界

OSPFは、隣接したルータから受け取った経路をそのまま信じます。

利用者の端末がつながるインターフェースは `passive-interface` にして、Helloを送らず隣接も作らないようにします。ルータ間でも認証を設定すると、誤って接続された機器や不正な機器の経路が入り込むのを防げます。

### 変更は「追加してから消す」、戻す手段を先に用意する

経路の付け替えでは、新しい経路を追加して通信を確認してから、古い経路を消します。断時間を最小にできます。

変更前後の `show ip route` を保存します。手順書には、確認コマンドと期待する結果、切り戻しの条件を事前に書いておきます。

リモートからの作業では、設定を誤ってつながらなくなった場合の戻し方も先に決めます。コンソール接続や、Cisco IOSの `reload in 10`（10分後に保存済みの設定で再起動する予約）などです。作業が成功したら `reload cancel` で予約を取り消します。

### 経路の変化を監視する

Neighborの状態変化はログに出力させ、syslog（ログを集めるための仕組み）で集めて監視します。

短時間にダウンとアップを繰り返すフラッピングは、回線品質やインターフェースの問題の兆候です。経路の数やDefault Routeの有無も監視すると、意図しない経路の追加や消失に早く気づけます。

### 切り分けは1ホップずつ、証拠で進める

到達しないときは、送信元から順に各ルータで `show ip route <宛先>` を実行し、選ばれた経路とNext Hopを確かめます。

tracerouteで同じアドレスが繰り返されればループ、途中で応答が途切れればその先の経路か復路を疑います。宛先側からも同じ手順を繰り返します。確かめた経路を構成図に書き込んでいくと、途切れた場所がはっきりします。

### まとめ

- 経路の設計理由と想定経路を文書に残し、実機と定期的に見比べる。
- Static RouteはNext Hopの停止に気づかない。冗長区間は動的ルーティングやBFDで検知する。
- 集約して広告するなら、集約範囲をNull0へ向けてループを防ぐ。
- 往路と復路の両方を確認し、変更は「追加してから消す」で戻し方を先に決める。
- 切り分けは1ホップずつ `show ip route <宛先>` で事実を集める。
