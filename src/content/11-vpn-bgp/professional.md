### 冗長化は、トンネル・機器・回線の単位で考える

**「トンネルが2本ある」だけでは、冗長とは限りません。**

AWSのSite-to-Site VPNの2本のトンネルは、両方とも設定して初めて冗長になります。1本しか設定していなければ、AWS側のメンテナンスで通信が止まることがあります。

両方設定しても、拠点側のルータ（CGW）が1台なら、その機器が単一障害点（そこが止まると全体が止まる箇所）として残ります。

| 備えたい障害 | 構成 |
| --- | --- |
| AWS側の片方のエンドポイント | 1つのVPN接続の2本のトンネルを両方使う |
| 拠点のルータや回線 | CGWを2台にしてVPN接続を2本用意し、BGPで切り替える |

切り替えは、実際に片側を止める試験で確かめておきます。

### アドレスの重複を、最初に潰す

拠点とVPCのCIDRが重複していると、VPNでつないでも正しくルーティングできません。

拠点、VPC、将来の接続先まで含めてアドレスを一元管理します（第2章）。トンネル内側の 169.254.x.x/30 も、ほかのトンネルと重複しないように割り当てます。重複が避けられない場合はNATが必要になり、構成と運用が複雑になります。

### 鍵と暗号方式は、運用の対象として管理する

事前共有鍵（PSK）は、十分に長く推測されにくいものにします。設定ファイルやチケットに平文で残さず、秘密情報の管理手段で保管します。担当者の異動時などに更新できる手順も用意します。

古い暗号方式やハッシュは使いません。両端で許可するプロポーザルを明示的に揃えます。両端が対応していれば、IKEv1よりIKEv2を選びます。

### 経路フィルタで、影響の広がりを防ぐ

**誤った経路の広告は、自組織だけでなく相手のネットワークにも影響します。**

eBGPでは、prefix-listで経路を絞ります。

- 送る経路：自組織のプレフィックスだけ
- 受け取る経路：想定したものだけ

受信する経路数に上限を決める設定（Cisco IOSの `neighbor ... maximum-prefix` など）も有効です。想定外の大量の経路から、機器を守れます。

### セッションと経路数を監視する

次の3つを監視し、変化したらアラートを上げます。

- トンネルの状態
- BGPセッションの状態（Establishedか）
- 受信・広告しているプレフィックス数

セッションが短時間に上下を繰り返すフラップは、回線品質やMTUの問題の手がかりになります。AWSではCloudWatch（AWSの監視サービス）のTunnelStateメトリクス、機器側ではsyslogを、時刻を揃えて集めます。

### BGPの変更は、効き方を予測してから入れる

LOCAL_PREFやAS_PATH prependの変更は、自組織の出口や、相手からの入口の通信を一斉に動かします。

1. 変更前に `show ip bgp <プレフィックス>` で、現在のBest Pathを記録する
2. 「どの経路がbestに変わるはずか」を予測して書いておく
3. 戻し用の設定を用意し、影響の小さい時間帯に1か所ずつ適用する
4. 変更後に、予測どおりの経路へ切り替わったかを確認する

prependは相手へのお願いにすぎず、相手がLOCAL_PREFで決めていれば効かない点も、予測に含めます。

### 両端のパラメータを1枚にまとめる

VPNは、両端の次の値が一致して初めて動きます。

```text
ピアIP（外側のアドレス）/ 暗号方式（プロポーザル）/ 鍵の更新間隔
トンネル内側のアドレス / ASN / 広告するプレフィックス
```

これらを両端で対比できるパラメータシートにまとめ、相手組織と共有します。「LOCAL_PREF 200は主回線」のような経路ポリシーの意図も記録します。

### 切り分けは、下の層から順に

どの段階で止まっているかを言葉にできれば、次に見るべき設定が決まります。

| 対象 | 確認の順序 |
| --- | --- |
| VPN | 相手のパブリックIPへの到達性 → トンネルのパラメータ（ピア、鍵、暗号方式）→ 両側の経路 → フィルタ |
| BGP | セッションがEstablishedか → 期待したプレフィックスを受信・広告しているか → Best Pathの選択理由 → 経路表に入っているか |

BGPの各段は、`show ip bgp summary`、`show ip bgp`、`show ip route` で確かめます。

### まとめ

- 冗長化は、トンネル・機器・回線のどの障害に備えるかで構成を決め、切り替え試験で確かめる。
- 拠点・VPC・トンネル内側のアドレスを一元管理し、重複を避ける。
- PSKは秘密情報として管理し、暗号方式は両端で明示的に揃える。
- eBGPはprefix-listで送受信の経路を絞り、変更はBest Pathの変化を予測してから入れる。
- 切り分けは、到達性 → トンネル → セッション → 経路 → フィルタの順に進める。
