## スイッチは「誰がどのポートにいるか」を覚えて転送する

博士：ノード君、オフィスの机の下をのぞいたことはあるかね。LANケーブルがのびているだろう。

ノード：はい。あのケーブル、どこにつながってるんですか？

博士：フロアの**スイッチ**だ。では質問だ。「営業と開発のネットワークを分けたい。でもスイッチを買い足す予算はない」。さて、どうする？

ノード：え〜っと…ケーブルを気合いで分ける、とか？

博士：気合いでは分けられん。そんなときに使うのが**VLAN**なのだ。

ノード：VLAN、名前だけは聞いたことあります。

博士：今回は順に3つの話をするぞ。スイッチがフレームをどのポートへ出すのか。VLANでLANをどう分けるのか。ケーブルを二重にしたときのループをどう防ぐのか、だ。

ノード：具体的には、何がわかるようになるんですか？

博士：うむ。まず、MACアドレスとEthernetフレームの形、それにARPで相手のMACアドレスを調べる流れ。次に、スイッチが「学習 → 検索 → 転送」でフレームの出し先を決める仕組みだ。

ノード：まだありそうですね。

博士：VLANの分け方、つまりアクセスポート・トランクポート・ネイティブVLAN。別のVLANと通信する方法として、Router on a StickとL3スイッチ。最後に、ループを防ぐSTPと、リンクを束ねるLACPだ。

ノード：盛りだくさんッスね…。

博士：心配はいらん。順番に行けば大丈夫だ。

### まず、言葉をそろえる

博士：最初に、この章で使う言葉をそろえておこう。表にするとこうだ。

| 用語 | 意味 |
| --- | --- |
| Ethernet | LANで、フレームを隣の機器へ運ぶための規格 |
| フレーム | Ethernetで運ぶデータのかたまり。宛先・送信元のMACアドレスが付く |
| MACアドレス | NIC（機器のネットワークの口）ごとに付いた48ビットの番号 |
| スイッチ | 同じLANの中で、フレームを宛先のいるポートへ転送する機器 |
| ポート | スイッチのケーブル差し込み口。`g0/1` などの名前で呼ぶ |
| ブロードキャスト | 同じネットワークの全員に一斉に送ること |
| VLAN | 1台のスイッチを、設定で複数のLANに分ける仕組み（Virtual LAN） |

ノード：MACアドレスとIPアドレスって、どっちも「宛先」ですよね。何が違うんですか？

博士：いい質問だ。IPアドレスは「最終的にどのホストへ」を表す。それに対してMACアドレスは「このリンク上のどの機器へ」を表すのだ。

ノード：つまり、IPアドレスが最終的な行き先で、MACアドレスは今いるリンクの上で渡す相手ってことですよね。

博士：その通り。

### MACアドレスとEthernetフレーム

ノード：MACアドレスって、どんな見た目なんですか？

博士：48ビットで、`00:1a:2b:3c:4d:5e` のように16進数6オクテットで書く。

ノード：6つに区切ってあるんですね。何か意味があるんですか？

博士：メーカーが割り当てたアドレスでは、先頭24ビットが**OUI**（Organizationally Unique Identifier：製造者の識別子）だ。

ノード：へぇ、先頭の半分は製造者の印なんですね。

博士：うむ。では、そのMACアドレスが付くフレームの形を見てみよう。一般的なEthernet IIフレームを図にするとこうなる。数字はバイト数だ。

```text
| 宛先MAC 6 | 送信元MAC 6 | EtherType 2 | データ 46〜1500 | FCS 4 |
```

ノード：宛先MACが先頭なんですね。EtherTypeって何ですか？

博士：**EtherType**は、中身の種類を示す番号だ。

| EtherType | 中身 |
| --- | --- |
| 0x0800 | IPv4 |
| 0x0806 | ARP |
| 0x86DD | IPv6 |

ノード：0x0806 はARPか。あとで出てきそうですね。

博士：うむ。そして最後の**FCS**（Frame Check Sequence）は、誤り検出用の値なのだ。

ノード：じゃあ、壊れてたら「もう一回送って」って頼むんですね。

博士：そこが違う。壊れたフレームは、受信側で破棄されるだけで、送り直しは要求されない。

ノード：え、捨てるだけですか？ データが消えちゃいますよ。

博士：失われたデータを送り直すのは、TCPなど上の層の仕事なのだ。

ノード：なるほど、役割分担なんですね。

### 宛先の種類：ユニキャスト、ブロードキャスト、マルチキャスト

博士：宛先MACには3つの種類がある。表にするとこうだ。

| 種類 | 宛先MAC | 届く範囲 |
| --- | --- | --- |
| ユニキャスト | 特定の1台のMAC | その1台 |
| ブロードキャスト | `ff:ff:ff:ff:ff:ff` | ブロードキャストドメイン（後述）内の全機器 |
| マルチキャスト | グループ用のMAC（IPv4なら `01:00:5e` で始まる） | そのグループ |

ノード：ブロードキャストは `ff:ff:ff:ff:ff:ff` なんですね。この「ブロードキャストドメイン」って何ですか？

博士：あとで説明するから、まあ待て。

ノード：はい。マルチキャストは、そのグループにだけ届くんですね。

博士：表の上ではそうだ。ただし、IGMP Snooping のないスイッチは、マルチキャストをブロードキャストと同じようにフラッディングする。

ノード：フラッディング？

博士：ほかの全ポートへ送ることだ。

ノード：じゃあ、IGMP Snoopingっていうのは？

博士：**IGMP**（Internet Group Management Protocol）は、マルチキャストへの参加を伝えるプロトコルだ。IGMP Snoopingは、それをスイッチが見て、必要なポートだけに流す機能なのだ。

ノード：つまり、参加の申し込みをスイッチがのぞき見して、流す先を絞るってことですね。

博士：うむ、そういうことだ。

### ARP：IPアドレスからMACアドレスを調べる

博士：さて、フレームを送るには、宛先のMACアドレスが必要だ。

ノード：でも、送る側が知ってるのって、相手のIPアドレスですよね。

博士：その通り。送り手が最初に知っているのは、宛先のIPアドレスだけだ。そこでIPv4のホストは、**ARP**（Address Resolution Protocol）で相手のMACアドレスを調べる。やり取りを図にするとこうなる。

```text
PC1 → 全員 (ff:ff:ff:ff:ff:ff)  : 192.168.1.20 を持っているのは誰？
PC2 → PC1  (ユニキャスト)       : 192.168.1.20 は 00:1a:2b:00:00:02 です
```

ノード：PC1が全員に「192.168.1.20 を持っているのは誰？」って聞いて、PC2だけがPC1に返事するんですね。

博士：うむ。問い合わせはブロードキャスト、応答はユニキャストだ。

ノード：これって、どんな相手でも調べられるんですか？ 遠くのサーバーとか。

博士：調べるのは、同じサブネットの相手だ。宛先が別のサブネットなら、調べる相手はDefault Gateway（LANの出口のルータ）になる。

ノード：送るたびに毎回聞くんですか？ 面倒そうです。

博士：結果は**ARPキャッシュ**に保存され、しばらくは問い合わせずに再利用される。Linuxでは `ip neigh` で確認できるぞ。

ノード：シミュレータでも同じ動きなんですか？

博士：そこは簡略化してある。

> シミュレータでの簡略化: ARPは要求と応答が同期的に完了し、キャッシュは120秒で消えます。実際のOSでは REACHABLE / STALE などの状態遷移があり、保持時間もOSや設定で異なります。

ノード：実際のOSだと、もっと細かいんですね。

### スイッチの基本動作：学習して、引いて、送る

ノード：いよいよスイッチですね。スイッチはどうやって、出すポートを決めるんですか？

博士：**MACアドレステーブル**を使う。どのMACアドレスがどのポートの先にいるかの表だ。フレームを受信するたびに、次の順で処理する。

```text
1. 受信：g0/1 でフレーム（送信元 aa:aa、宛先 bb:bb）を受け取る
2. 学習：「VLAN 10 の aa:aa は g0/1 の先にいる」とMACアドレステーブルに記録
3. 検索：宛先 bb:bb をテーブルで探す
4. 転送：見つかれば、そのポートだけへ送る
         見つからない・ブロードキャストなら、同じVLANの受信ポート以外へフラッディング
```

ノード：受信、学習、検索、転送…。見つからないときは、同じVLANの受信ポート以外に全部送るんですね。

博士：そうだ。3台のPCがつながったスイッチで、実際の流れを追ってみよう。

```text
g0/1 = PC1 (aa:aa)   g0/2 = PC2 (bb:bb)   g0/3 = PC3 (cc:cc)   すべて VLAN 10

① PC1 → PC2（最初の1回）
   学習：aa:aa は g0/1
   検索：bb:bb は未学習 → g0/2 と g0/3 へフラッディング（PC3 にも届く）
② PC2 → PC1（返信）
   学習：bb:bb は g0/2
   検索：aa:aa は g0/1 → g0/1 だけへ送る
③ 以降の PC1 → PC2
   bb:bb は g0/2 → g0/2 だけへ送る（PC3 には届かない）
```

ノード：最初の1回は、PC3にも届いちゃうんですね。

博士：うむ。bb:bb をまだ学習していないからな。PC2が返信した時点で、bb:bb の居場所がわかる。

ノード：で、③からは g0/2 だけに送る、と。

博士：その通り。ちなみにpingの場合、最初に流れるのはARPのブロードキャストなので、これも必ずフラッディングされる。

ノード：あれ？ 学習って、宛先MACも使えば、もっと早く覚えられませんか？

博士：それはできないのだ。学習に使うのは、**送信元MACだけ**だ。

ノード：どうしてですか？

博士：スイッチは、ある機器が「どのポートの先にいるか」を、その機器が送ってきたフレームからしか知りようがないからだ。宛先MACは、居場所の手がかりにならない。

ノード：なるほど。手紙の宛名を見ても、その人が今どこにいるかはわからないですもんね。

博士：うむ。それと、宛先が受信ポートと同じ側にいる場合は、どこにも転送しない。

ノード：学習した内容って、ずっと残るんですか？

博士：一定時間フレームが来なければ消える。これを**エージング**という。IEEE 802.1Dの推奨値もCiscoの既定値も300秒だ。

ノード：300秒ってことは、5分ですね。

博士：機器を別のポートへ移したのに、しばらく通信できない。この現象には、このテーブルが関係していることがある。そこは覚えておきたまえ。

ノード：はい、覚えておきます。

### ブロードキャストドメインとコリジョンドメイン

ノード：さっき後回しにした「ブロードキャストドメイン」、そろそろ教えてください。

博士：うむ。よく似た言葉のコリジョンドメインと並べて、表にするとこうだ。

| | ブロードキャストドメイン | コリジョンドメイン |
| --- | --- | --- |
| 意味 | ブロードキャストが届く範囲 | 半二重の共有媒体で、送信が衝突しうる範囲 |
| ハブ | 全ポートで1つ | 全ポートで1つ |
| スイッチ（VLANなし） | 全ポートで1つ | ポートごとに分かれる |
| ルータ | 境界になる（ブロードキャストを転送しない） | 境界になる |

ノード：ハブは両方とも全ポートで1つ。スイッチは、コリジョンドメインだけポートごとに分かれるんですね。

博士：そうだ。そしてルータは、どちらも境界になる。ブロードキャストを転送しないからな。

ノード：ブロードキャストドメインって、結局どのくらいの範囲なんですか？

博士：**ブロードキャストドメイン**は、ARPが届く範囲と同じだ。ブロードキャストは範囲内の全機器が受け取って処理するので、広すぎるとむだな負荷になる。

ノード：コリジョンドメインのほうは？

博士：**コリジョンドメイン**は、半二重（送信と受信を同時にできない方式）の共有媒体で問題になる。現在主流の全二重リンクでは、衝突そのものが起きないのだ。

ノード：へぇ、全二重なら衝突の心配はないんですね。

### VLAN：1台のスイッチを論理的に分ける

博士：ここで最初の話に戻るぞ。**VLAN**は、スイッチを複数のブロードキャストドメインに分けるのだ。

ノード：1台のスイッチなのに、分けられるんですか？

博士：うむ。VLAN 10 のフレームは、VLAN 20 のポートへは出ない。通常、1つのVLANに1つのIPサブネットを対応させる。

ノード：なるほど。営業はVLAN 10、開発はVLAN 20、みたいにするんですね。

博士：そうだ。この章の後半では、次の構成を使う。

```text
SW1  g0/1 = PC1（VLAN 10）  g0/2 = PC2（VLAN 20）  g0/3 = SW2へのトランク  g0/8 = R1へのトランク
SW2  g0/1 = PC3（VLAN 10）  g0/2 = PC4（VLAN 20）  g0/3 = SW1へのトランク

VLAN 10（SALES）192.168.10.0/24：PC1 .11、PC3 .13、ゲートウェイ .1（R1）
VLAN 20（DEV）  192.168.20.0/24：PC2 .12、PC4 .14、ゲートウェイ .1（R1）
```

ノード：SALESが営業、DEVが開発ですね。PC1とPC3がVLAN 10で、PC2とPC4がVLAN 20か。

博士：うむ。ここで大事なことがある。VLANが違えば、ブロードキャストドメインも違う。

ノード：はい。

博士：そのため、**同じサブネットのIPを設定したPCでも、別のVLANのポートにつなぐと通信できない。**

ノード：え、IPはちゃんと合ってるのにですか？

博士：ARPの問い合わせが相手に届かないからだ。

ノード：そっか。相手のMACアドレスがわからないと、フレームを送れないんでしたね。

#### アクセスポートとトランクポート

ノード：図にあった「トランク」って何ですか？

博士：スイッチのポートの使い方には2種類ある。表にするとこうだ。

| | アクセスポート | トランクポート |
| --- | --- | --- |
| 運ぶVLAN | 1つだけ | 複数 |
| フレーム | タグなし | 802.1Qタグ付き（ネイティブVLANを除く） |
| つなぐ相手 | PCやサーバー（VLANを意識しない） | スイッチどうし、ルータなど |

ノード：アクセスポートはVLANを1つだけ運んで、PCやサーバーをつなぐ。トランクポートは複数のVLANを運ぶんですね。でも、1本のケーブルに複数のVLANが混ざったら、区別がつかなくなりませんか？

博士：だから、トランクではフレームに**802.1Qタグ**を付けて区別するのだ。どのVLANのフレームかを示す、4バイトの印だ。

ノード：タグは、フレームのどこに付くんですか？

博士：送信元MACの直後に挿入される。図にするとこうなる。

```text
| 宛先MAC | 送信元MAC | TPID 0x8100 | PCP 3bit | DEI 1bit | VID 12bit | EtherType | データ | FCS |
```

ノード：このVIDっていうのが、VLANの番号ですか？

博士：その通り。**VID**（VLAN ID）は12ビットだ。0と4095は予約されているので、使えるVLAN IDは1〜4094になる。

ノード：タグを付けたら、フレームの中身が変わりますよね。FCSはどうなるんですか？

博士：いいところに気づいたな。タグを付け外しすると、FCSは再計算される。

ノード：なるほど、ちゃんと計算し直すんですね。

博士：PC1からPC3（どちらもVLAN 10）へ送ると、タグは次のように付け外しされる。

```text
PC1 ──タグなし──> SW1 g0/1（アクセス VLAN 10）   「VLAN 10 のフレーム」と判断
SW1 g0/3 ──タグ VID=10──> SW2 g0/3（トランク）    タグを見て VLAN 10 と判断
SW2 g0/1（アクセス VLAN 10）──タグなし──> PC3      タグを外して渡す
```

ノード：PC1とPC3はタグなしのままで、スイッチどうしの間だけタグが付くんですね。

博士：うむ。VLANを意識しないPCには、タグを外して渡すのだ。

ノード：トランクって、どのVLANでも通すんですか？

博士：`switchport trunk allowed vlan` で、運ぶVLANを限定できる。**許可リストにないVLANのフレームは、そのトランクを通らない。**

ノード：リストに入れ忘れたら、そのVLANは通らないってことですね。

博士：そうだ。もう一つ。スイッチは、VLANデータベースに存在しないVLANのフレームを転送しない。`vlan 10` で作成してから使うといい。

ノード：先にVLANを作っておかないとダメなんですね。

博士：うむ。ここもシミュレータでは簡略化しているぞ。

> シミュレータでの簡略化: アクセスポートはタグ付きフレームをすべて破棄します。実機では音声VLAN（voice VLAN）のように、アクセスポートでタグ付きフレームを扱う構成もあります。

#### ネイティブVLAN

ノード：さっきの表に「ネイティブVLANを除く」ってありましたけど…。

博士：トランク上でタグを付けずに送受信されるVLANを、**ネイティブVLAN**という。Cisco機器での呼び方だ。

ノード：トランクなのに、タグなしのVLANがあるんですね。

博士：うむ。Cisco機器の既定はVLAN 1だ。タグなしで受信したフレームは、ネイティブVLANに所属するとみなされる。

ノード：両端でネイティブVLANが違ったら、どうなるんですか？

博士：片側でネイティブVLANのフレームは、タグなしで送られる。相手側では、それが相手のネイティブVLAN、つまり別のVLANとして受け取られる。

ノード：え、それって…。

博士：その結果、**VLAN間でフレームが漏れる**のだ。

ノード：せっかく分けたのに、混ざっちゃうんですね。

博士：だから、ユーザー用のVLANをネイティブVLANにしない、両端で必ず一致させる。これが基本だ。

### VLAN間ルーティング

ノード：でも博士、営業と開発でも、たまには通信したいですよね。VLANが違うときはどうするんですか？

博士：VLANが違えばサブネットも違う。だから、VLANをまたぐ通信には、ルータなどのL3（IPを扱う層）の機器が必要なのだ。

ノード：VLANの数だけ、ルータにケーブルをつなぐんですか？

博士：そうとは限らん。**Router on a Stick**という方法がある。ルータの1つの物理ポートをトランクにつなぎ、VLANごとにサブインターフェースを作るのだ。

ノード：サブインターフェース？

博士：1つの物理ポートを、論理的に分けたものだ。各サブインターフェースのIPが、そのVLANのDefault Gatewayになる。設定はこうだ。

```text
interface g0/0.10
 encapsulation dot1q 10
 ip address 192.168.10.1/24
interface g0/0.20
 encapsulation dot1q 20
 ip address 192.168.20.1/24
```

ノード：`encapsulation dot1q 10` って何ですか？

博士：「このサブインターフェースはVLAN 10（タグ10）のフレームを扱う」という意味だ。PC1（VLAN 10）からPC2（VLAN 20）へは、次のように届く。

```text
PC1 → SW1 → g0/8（タグ10）→ R1 g0/0.10
R1：宛先 192.168.20.12 は g0/0.20 に直結 → タグ20を付けて、同じ物理リンクで送り返す
R1 g0/0.20 → SW1 g0/8（タグ20）→ g0/2 → PC2
```

ノード：タグ10でR1に行って、タグ20を付けて、同じケーブルで戻ってくるんですね。

博士：うむ。ここで注意だ。**R1につながるSW1のポートは、トランクでなければならない。**

ノード：アクセスポートのままだと、どうなるんですか？

博士：タグ付きフレームが流れず、R1のサブインターフェースにARPが届かないのだ。

ノード：それに、VLAN間の通信が、全部この1本を行ったり来たりするんですよね。混みそうです。

博士：鋭いな。VLAN間の通信はすべて同じ1本のリンクを往復するので、帯域がボトルネックになりやすい構成だ。

ノード：ほかの方法はないんですか？

博士：**L3スイッチ**（ルーティングもできるスイッチ）を使う方法がある。VLANごとの仮想インターフェース **SVI**（Switched Virtual Interface）にIPを設定し、スイッチの内部でルーティングするのだ。

```text
interface vlan10
 ip address 192.168.10.1/24
```

ノード：`interface vlan10` にIPを付けるんですね。ルータとつなぐポートはどうするんですか？

博士：ルータとの接続などに使う物理ポートは、`no switchport` でルーテッドポート（ルータのポートのように使うポート）にできる。

ノード：なるほど。

博士：なお、実機のCisco IOSでは `ip address 192.168.10.1 255.255.255.0` のようにマスクで書く。シミュレータはどちらの形式も受け付けるぞ。

ノード：実機では書き方に気をつけます。

博士：それと、実機のL3スイッチは、機種によって `ip routing` でルーティングを有効にする必要がある。

ノード：はい、それも覚えておきます。

### リンクの速度と、ポートの種類

ノード：さっき、1本のリンクを全部の通信が行き来すると「帯域がボトルネックになる」って出てきましたよね。帯域って、そもそも何ですか？

博士：よい質問だ。リンクには**速度**がある。1秒間に運べるビットの数で、単位は **bps**（bits per second）だ。

```text
100 Mbps   = 1秒に 1億ビット      （M = メガ = 100万）
1 Gbps     = 1,000 Mbps           （G = ギガ = 10億）
10 Gbps / 25 Gbps / 40 Gbps / 100 Gbps …
```

ノード：1 Gbps は 1,000 Mbps なんですね。

博士：うむ。ここで気をつけたいのが、ビット（b）とバイト（B）の違いだ。1バイトは8ビット。10 GB（ギガバイト）のファイルは 80 Gb（ギガビット）なので、1 Gbps のリンクでも理論上80秒かかる。

ノード：小文字のbと大文字のBで、8倍も違うんですね…。

博士：言葉もそろえておこう。リンクが運べる最大の速さを**帯域**（bandwidth）、実際に出た速さを**スループット**（throughput）という。インターフェースの速度（interface speed）やリンク速度（link speed）は、帯域を決める値だ。

ノード：スループットは、帯域より小さくなるんですか？

博士：そうだ。ヘッダの分や再送、混雑の分だけ下がる。そしてもっと大事なのが、**経路の途中で一番遅いリンクが上限になる**ことだ。

```text
PC ──10G── SW1 ──1G── SW2 ──10G── Server
                 ↑
         ここがボトルネック（1 Gbps）
```

ノード：両端が10Gでも、真ん中が1Gなら…1本の転送は1 Gbpsまで？

博士：その通り。速度は足し算ではない。最も遅い区間を**ボトルネック**（bottleneck）という。「経路がある＝十分な速さが出る」ではないのだ。

ノード：pingが通っても、速いとは限らないんですね。

博士：うむ。もう1つ、物理的な話もしておこう。ポートには形と対応する速度がある。

| ポート・部品 | 主な速度 | 媒体 |
| --- | --- | --- |
| RJ45 | 100M / 1G（10GBASE-T 対応なら 10G） | 銅線（UTPケーブル） |
| SFP | 1G | 光モジュール、銅線モジュール |
| SFP+ | 10G | 光モジュール、DAC |
| SFP28 | 25G | 光モジュール、DAC |
| QSFP+ / QSFP28 | 40G / 100G | 光モジュール、DAC |

ノード：SFPとかQSFPって、穴（スロット）の形なんですか？

博士：そうだ。そこへ**トランシーバ**（光モジュールなど）を挿し、光ファイバーをつなぐ。**DAC**（Direct Attach Cable）は、モジュールと銅のケーブルが一体になった短距離用の部品だ。

ノード：じゃあ、形が合えば何でもつながりますか？

博士：そうはいかない。両端で、形・速度・媒体がそろう必要がある。たとえば光なら、短距離用のマルチモード（SR）と長距離用のシングルモード（LR）は、ファイバーも光の波長も違うので、つながらない。

ノード：型番を全部覚えないといけないんですか…？

博士：いや、覚えなくてよい。「ポートには対応する媒体・速度・規格があり、両端でそろえる必要がある」と知っていれば十分だ。具体的な組み合わせは、機器の資料で確かめるものだ。

ノード：それなら安心です。

> シミュレータでの簡略化: 速度はリンク（ケーブル）単位で持ちます。構成図でケーブルを選ぶか、`interface <ポート>` → `speed 10000` で変えると、両端が同時に変わります。オートネゴシエーション・二重化（duplex）・光モジュールの種類は再現しません。ポートと媒体の組み合わせは、Visualステップの対応表で確かめられます。

### STP：冗長なリンクがループにならないように

博士：さて、スイッチ間の経路を複数用意すると、1本が切れても通信を続けられる。

ノード：じゃあ、ケーブルはたくさんつないだほうが安心ですね！

博士：相変わらず気が早いな。経路が複数あると、スイッチの間にフレームがぐるりと回れる輪、つまりループができる。しかも**EthernetフレームにはTTLがない**のだ。

ノード：TTLがないと、どうなるんですか？

博士：ループがあると、ブロードキャストが複製され続けて**ブロードキャストストーム**になる。

ノード：ぐるぐる回り続けるんですね…。

博士：同じ送信元MACが複数のポートで交互に学習される**MACフラッピング**も起こる。

ノード：テーブルがめちゃくちゃになりそうです。どうやって防ぐんですか？

博士：そこで**STP**（Spanning Tree Protocol。IEEE 802.1D）の出番だ。一部のポートを転送しない状態にして、論理的にループのない木構造を作るのだ。

ノード：止めるポートは、どうやって決めるんですか？

博士：4つの手順で決める。1つ目、**Root Bridge**（木の根になるスイッチ）を1台選ぶ。Bridge ID（プライオリティ＋MACアドレス）が最も小さいスイッチだ。

ノード：プライオリティって、自分で決められるんですか？

博士：うむ。プライオリティの既定値は32768で、4096単位で設定する。

ノード：2つ目は？

博士：Root以外の各スイッチは、Rootへのパスコストの合計が最小のポートを **Root Port** にする。パスコストは、速いリンクほど小さい値だ。

ノード：Rootへの近道になるポートですね。

博士：3つ目。各リンクで、Rootに近い側のポートを **Designated Port** にする。

ノード：で、4つ目が…。

博士：どちらにもならないポートは転送を止める。RSTP＝STPの改良版の用語では、**Alternate Port** という。

ノード：なるほど。でも言葉だけだと、ちょっとイメージしにくいッスね。

博士：では、3台のスイッチを三角形につないだ例で考えよう。図にするとこうなる。

```text
SW1 ──────── SW2
  \          /
   \        /
     SW3        SW3 を priority 4096 にして Root Bridge にする

SW1：SW3 への直結ポートが Root Port
SW2：SW3 への直結ポートが Root Port
SW3：Root Bridge のポートはすべて Designated Port
SW1–SW2 のリンク：片側（Bridge IDが小さい側）が Designated Port、もう片側がブロック
```

ノード：SW3がRootで、SW1もSW2も、SW3への直結ポートがRoot Portなんですね。

博士：うむ。そしてSW1–SW2 のリンクでは、Bridge IDが小さい側がDesignated Port、もう片側がブロックだ。

ノード：リンク3本のうち、止まるのは1か所だけですか？

博士：リンクの速度がすべて同じなら、このようにSW1–SW2 間の1か所だけが止まり、ループが切れる。

ノード：Root Bridgeって、放っておいても決まるんですよね？

博士：決まりはする。だが、Root Bridgeは意図して決めるものだ。MACアドレスの大小に任せると、古い機器や末端のスイッチがRootになることがある。

ノード：だからこの例では、SW3を priority 4096 にしてRootにしてるんですね。

博士：その通り。シミュレータでの扱いも確認しておくといい。

> シミュレータでの簡略化: STPは単一インスタンスで、定常状態のポートの役割（root / designated / alternate）だけを計算します。BPDU（STPの制御メッセージ）の交換やタイマー、収束中の状態遷移は再現しません。STPを無効にしてループを作ると、フレームの複製を256回で打ち切ります。実機のストームは止まらず、リンク帯域や機器のCPUを使い切ります。

ノード：実機だと256回で止まってくれないんですか…怖いですね。

博士：うむ。だからこそ、STPが大事なのだ。

### Link Aggregation：複数のリンクを1本の論理リンクとして束ねる

#### なぜ束ねるのか

ノード：STPでループを防ぐのはわかりました。ところで、スイッチどうしを1本のリンクだけでつなぐのって、大丈夫なんですか？

博士：鋭いな。1本のリンクには限界がある。1つ目は**帯域の上限**、2つ目は**ケーブルの障害**、3つ目は**ポートの故障**だ。

ノード：じゃあ、スイッチの間をケーブル2本でつなげば、速くて切れにくくなりますね！

博士：さっきのSTPを思い出してみたまえ。同じ2台の間に2本つなぐと、それもループだ。STPは片方をブロックするので、使えるのは1本だけになる。

ノード：あ、そうでした。2本目は待機しているだけ…。

博士：そこで、**複数の物理リンクを、1つの論理リンクとして扱う**。これが**Link Aggregation**（リンクアグリゲーション）、束ねた全体を**LAG**（Link Aggregation Group）という。

```text
物理（2本のケーブル）        論理（1本のリンク）

SW1 ───── SW2               SW1 ═════ SW2
SW1 ───── SW2                    po1
```

ノード：束ねた「po1」が、1本のリンクに見えるんですね。

博士：うむ。Cisco機器では、束ねた論理インターフェースを **Port-channel**、技術の名前を **EtherChannel** と呼ぶ。Linuxでは bonding や teaming という。束ねられる個々のポートは**メンバー**だ。

ノード：呼び方がたくさんありますね。

博士：中身は同じ考え方だ。STPから見えるのも po1 の1本だけなので、ブロックされずに2本とも使える。

#### static と LACP

ノード：束ねる設定は、片方のスイッチだけでいいんですか？

博士：両端で設定する。束ね方は2種類ある。1つ目は**static**（静的）で、Cisco機器では `mode on` だ。相手と何も確認せずに束ねる。

ノード：2つ目は？

博士：**LACP**（Link Aggregation Control Protocol）だ。LACPDUという制御メッセージを交換して、「このリンクは同じ相手と、同じ条件でつながっているか」を確かめてから束ねる。

ノード：確かめるほうが安心ですね。LACPにも設定の種類があるんですか？

博士：**active** と **passive** がある。activeは自分からLACPDUを送る。passiveは、送られてきたら応える。

| SW1 | SW2 | 束ねられる？ |
| --- | --- | --- |
| active | active | ○ |
| active | passive | ○ |
| passive | passive | ×（どちらも話しかけない） |
| on（static） | on（static） | ○（確認はしない） |
| on | active / passive | ×（方式が違う） |

ノード：passive同士は、お互いに待っているだけなんですね。

博士：そうだ。staticとLACPも組み合わせられない。staticは対向を確認しないので、片側だけ束ねるとループや片側だけの転送が起きる。そのため実務ではLACPが推奨される。

ノード：LACPが確かめる「同じ条件」っていうのは？

博士：速度などの条件がそろわないメンバーは、束ねられずに**suspended**（停止）になる。たとえば1本だけ100 Mbpsでリンクしていると、そのメンバーは使われない。

```text
SW1(config)# interface range g0/7-8
SW1(config-if-range)# channel-group 1 mode active
Creating a port-channel interface po1
SW1(config-if-range)# exit
SW1(config)# interface po1
SW1(config-if)# switchport mode trunk
SW1(config-if)# switchport trunk allowed vlan 10,20

SW1# show etherchannel summary
Group  Port-channel  Protocol    Ports
1      po1(SU)         LACP      g0/7(P)     g0/8(P)
```

ノード：この (P) とか (SU) って何ですか？

博士：メンバーの (P) は、束ねられて使用中という意味だ。po1 の (SU) は、S がL2、U が使用中を表す。(s) は suspended、(D) は Down を表す。

#### 帯域についての大きな誤解

ノード：10 Gbps を2本束ねたら、20 Gbps ですよね。どの通信も2倍速くなる！

博士：そこが一番大事な誤解だ。束ねた全体の容量、**aggregate bandwidth**（集約帯域）は20 Gbps相当だ。だが、**1本のTCP接続が20 Gbpsになるわけではない**。

ノード：えっ、どうしてですか？

博士：スイッチは、フレームをどのメンバーに流すかを**ハッシュ**で決めるからだ。ハッシュとは、いくつかの値から決まった計算をして、番号を1つ取り出すことだ。

ノード：どんな値を使うんですか？

博士：機器と設定によって違う。送信元・宛先のMACアドレス、送信元・宛先のIPアドレス、TCP/UDPのポート番号などだ。IPアドレス・プロトコル・ポート番号の5つの組を**5-tuple**（ファイブタプル）という。

ノード：同じ通信なら、値も同じですよね。

博士：その通り。だから同じフロー（同じ5-tupleの通信）は、いつも同じ1本のメンバーを通る。到着順が入れ替わらないようにするためだ。

```text
Flow A（PC1:49152 → Server:443） → メンバー g0/7
Flow B（PC1:49153 → Server:443） → メンバー g0/8
Flow C（PC2:50001 → Server:443） → メンバー g0/7
```

ノード：だから1つのフローは、メンバー1本分の10 Gbpsまで…。たくさんのフローがあれば、2本に分かれて合計20 Gbps近く使える、ということですね。

博士：うむ。運が悪いと、大きなフローが同じメンバーに集まることもある。それに、MACアドレスだけでハッシュする設定だと、同じ2台の間の通信はすべて同じメンバーに乗ってしまう。

ノード：束ねても速くならない場合があるんですね…。

#### 1本壊れたら、全部壊れたら

ノード：メンバーのケーブルが1本切れたら、どうなるんですか？

博士：論理リンクpo1はUpのままだ。通信は残りのメンバーへ移る。ただし、使える帯域は減る。この「動いているが能力が落ちた」状態を**縮退**（degraded）という。

ノード：STPは計算し直さないんですか？

博士：STPから見たポートはpo1のままなので、計算し直さない。それも束ねる利点だ。ただし、全メンバーがDownすると、po1もDownする。

#### VLANやSTPとの関係

ノード：VLANの設定は、メンバーとpo1のどちらに入れるんですか？

博士：po1だ。po1をアクセスポートにも、トランクにもできる。許可VLANやネイティブVLANの考え方も、普通のトランクと同じだ。両端のpo1で、そろえる必要があるのも同じだ。

ノード：LACPがあれば、STPはいらなくなりますか？

博士：いや、役割が違う。LACPは「同じ相手との並列リンクを1本にまとめる」仕組みで、STPは「スイッチ全体でループを作らない」仕組みだ。束ねたあとも、ネットワークのほかの場所のループはSTPが防ぐ。競合する技術ではないのだ。

ノード：協力して働く仲間なんですね。

> シミュレータでの簡略化: LACPは定常状態だけを計算します。LACPDUのタイマー、system priority / key、fast / slow rate、ポート数の上限（max-bundle・min-links）は再現しません。メンバーの条件は「同じ相手機器・同じ相手のグループ・同じ速度」で判定し、メンバー自身のL2設定は使わずPort-channelの設定を使います。ハッシュは教育用の関数で、実機の計算方法とは異なります。static（mode on）の食い違いは、実機では検出できない場合がありますが、シミュレータでは不整合としてメンバーを使いません。

### 発展：MACアドレスの特別なビットと、規格の細かい話

博士：ここからは発展だ。今は読み飛ばしてもかまわないぞ。

ノード：せっかくなので聞きます。

博士：まず、**MACアドレスの特別なビット**だ。先頭オクテットの最下位ビットが1なら、グループ（マルチキャスト）宛てだ。

ノード：さっきの `01:00:5e` も、先頭が 01 だから、最下位ビットが1ですね。

博士：その通り。その隣のビットが1なら、ローカルに管理された（メーカーの割り当てではない）アドレスだ。

ノード：802.1Qタグにあった、TPIDやPCP、DEIは何ですか？

博士：**TPID**（Tag Protocol Identifier）は、ここからタグが始まることを示す値で、0x8100 だ。**PCP**（Priority Code Point）はフレームの優先度、**DEI**（Drop Eligible Indicator）は混雑時に捨ててよいかの印だ。

ノード：STPのパスコストは、具体的にどんな値なんですか？

博士：旧来の短い方式では、1Gbpsが4、100Mbpsが19だ。

ノード：速いリンクほど小さい値、のとおりですね。RSTPも出てきましたけど…。

博士：従来のSTPは、トポロジ変化後の収束に数十秒かかる。**RSTP**（IEEE 802.1w、現在は802.1Dに統合）は、隣接スイッチ間の合意の仕組みで収束を大幅に速めるのだ。

ノード：実機では、どんな方式が使われてるんですか？

博士：実機のCisco機器では、VLANごとにSTPを動かす方式（PVST+ / Rapid PVST+）がよく使われる。

ノード：最後に、LACPの規格は？

博士：IEEE 802.3ad として作られ、現在は 802.1AX だ。

ノード：規格の番号も変わるんですね。

### よくある誤解

博士：では、よくある誤解を確認しよう。ノード君、スイッチは何を見て学習するんだったかな。

ノード：え〜っと、スイッチは宛先MACを見て学習する…んでしたっけ？

博士：違う。学習に使うのは送信元MACだ。宛先MACは、テーブルを引くために使う。

ノード：あ、そうでした。次は大丈夫です。IPが同じサブネットなら、どのポートにつないでも通信できますよね？

博士：VLANが違えばブロードキャストドメインが分かれ、ARPが届かない。

ノード：そうだった…。じゃあ、リンクを増やして冗長にすれば、それだけ安全ですよね？

博士：STPがなければループになり、ブロードキャストストームでLAN全体が止まる。

ノード：うっ。でも、LACPで2本束ねれば、1つの通信も2倍速くなりますよね？

博士：振り分けはフローごとなので、1つのフローはメンバー1本分の速度までだ。

ノード：うぅ…。でも、両端が10Gのポートなら、途中に1Gのリンクがあっても10Gで送れますよね？

博士：1つの転送は、通る道で一番遅いリンク（ボトルネック）の速さまでだ。

ノード：最後こそは！ LAGのメンバーが1本切れたら、論理リンクごとDownしますよね？

博士：残りのメンバーがあれば論理リンクはUpのままで、帯域が減るだけだ。全メンバーがDownしたときに、論理リンクもDownする。

ノード：全部ひっかかりました…。

博士：だから確かめておくのだよ。

### 確認してみよう

博士：では問題だ。

1. スイッチがフレームを受信したとき、学習に使うのはどのMACアドレスですか？
2. 同じサブネットのIPを設定した2台のPCを、別のVLANのアクセスポートにつなぎました。通信できますか？
3. Router on a Stickで、R1につながるスイッチのポートはアクセスとトランクのどちらにしますか？
4. 1 Gbps のメンバー2本のLAGで、1本のTCP接続が使える速さの上限は？

ノード：1は、送信元MACアドレスです。受信ポートと結び付けて記録します。

博士：正解だ。2は？

ノード：できません。ARPが相手に届かないからです。

博士：その通り。3は？

- **スイッチの学習の可視化**（Visualステップ）：PC間でpingを送り、SW1が「学習」と「転送判断」をどう行うかを1つずつ確認できます。
- **ブロードキャストの届く範囲**：送信元を選ぶと、VLAN 10 / 20 のどの機器にブロードキャストが届くかが光って表示されます。
- `vlan 10` → `name SALES` でVLANを作り、`show vlan brief` で確認する。
- `switchport mode access` / `switchport access vlan 10` と、`switchport mode trunk` / `switchport trunk allowed vlan 10,20` / `switchport trunk native vlan 99` を設定し、`show interfaces trunk` で確認する。
- PC間でpingした後に `show mac address-table` を見て、学習されたMACとポートを確認する。`clear mac address-table` で消して、フラッディングからやり直す。
- PCで `ip neigh` / `arp -n` を実行し、ARPの結果を確認する。`tcpdump -e` でMACアドレスを含めて表示する。
- `spanning-tree priority 4096` でRoot Bridgeを指定し、`show spanning-tree` でポートの役割を確認する。`no spanning-tree` でループの危険性を観察する。
- **リンク速度とボトルネック**・**ポートと媒体の組み合わせ**・**Link Aggregation**（Visualステップ）：速度を変えて上限が変わる様子、モジュールの組み合わせ、メンバーの状態と8本のフローの振り分けを確かめられます。

#### 用語メモ

- **MACアドレステーブル**［MAC address table］：どのMACアドレスがどのポートの先にいるかを、スイッチが記録する表。
- **フラッディング**［flooding］：フレームを受信ポート以外のほかの全ポートへ送ること。
- **ARP**［Address Resolution Protocol］：IPv4で、IPアドレスから相手のMACアドレスを調べるプロトコル。
- **ブロードキャストドメイン**［broadcast domain］：ブロードキャストが届く範囲。ARPが届く範囲と同じ。
- **VLAN**［Virtual LAN］：1台のスイッチを、設定で複数のブロードキャストドメインに分ける仕組み。
- **802.1Qタグ**：トランクで、どのVLANのフレームかを示す4バイトの印。送信元MACの直後に入る。
- **ネイティブVLAN**［native VLAN］：トランク上でタグを付けずに送受信されるVLAN。Cisco機器の既定はVLAN 1。
- **SVI**［Switched Virtual Interface］：L3スイッチで、VLANごとに作る仮想インターフェース。
- **STP**［Spanning Tree Protocol］：一部のポートを転送しない状態にして、ループのない木構造を作るプロトコル。
- **LACP**［Link Aggregation Control Protocol］：複数の物理リンクを1本の論理リンクに束ねるとき、両端で条件を確かめ合う制御プロトコル。
- **LAG / Port-channel / EtherChannel**：束ねた論理リンク（LAG）。Cisco機器では論理インターフェースを Port-channel、技術を EtherChannel と呼ぶ。束ねられる物理ポートはメンバー。
- **帯域・スループット**［bandwidth / throughput］：リンクが運べる最大の速さ／実際に出た速さ。単位は bps（1 Gbps = 1,000 Mbps）。
- **ボトルネック**［bottleneck］：経路の中で最も遅い区間。1つの転送の上限を決める。
- **集約帯域**［aggregate bandwidth］：束ねたリンク全体の容量。1つのフローが使えるのは、そのうちメンバー1本分。
- **トランシーバ / DAC**：SFPなどのスロットに挿す光・銅線のモジュール／モジュールとケーブルが一体の短距離用部品。

#### ノード君の今日のポイント

- スイッチは送信元MACで「誰がどのポートにいるか」を学習し、宛先MACでテーブルを引く。未学習の宛先やブロードキャストは、同じVLANの受信ポート以外へフラッディングする。
- VLANはブロードキャストドメインを分ける。VLANが違えば、同じサブネットのIPでもARPが届かない。
- トランクは802.1Qタグで複数のVLANを運ぶ。許可VLANとネイティブVLANは両端でそろえる。
- VLAN間の通信にはL3の機器が必要。Router on a Stickでは、ルータ側のスイッチポートをトランクにする。
- EthernetにはTTLがないので、冗長なリンクはSTPでループを切る。
- リンクには速度がある。1つの転送の上限は、通る道で一番遅いリンク（ボトルネック）で決まる。ポートと媒体は、形・速度・規格を両端でそろえる。
- 同じ相手との並列リンクは、Link Aggregation（LACP）で1つの論理リンクに束ねる。STPから見ても1本なので、ブロックされずに全部使える。
- LACPで束ねても、振り分けはフローごとのハッシュ。1つのフローはメンバー1本分の速度まで。合計（aggregate）を使えるのは、たくさんのフローがあるとき。
- メンバーが1本切れても論理リンクは続き、帯域が減るだけ。全部切れたら論理リンクもDown。VLANの設定は Port-channel に入れる。
